## 十一、技术执行工具选择规范

### 判断原则

| 场景特征 | 使用工具 |
|---------|----------|
| 单文件、单位置、新增代码、改动<30行 | Claude Code |
| 多文件同步、涉及删除/替换、多步骤有依赖、改动>30行 | PowerShell + Python 脚本 |

### Claude Code 适用场景
- 单一明确任务，一句话可完整描述
- 只新增代码，不涉及删除或替换现有逻辑
- 读取文件内容用于分析（只读任务）

### PowerShell + Python 适用场景
- 多文件同步改动
- 需要精确行号的替换/删除操作
- 3步以上有顺序依赖的改动
- Claude Code 出现「读文件死循环」时立即切换

### PowerShell 操作规范（Windows 环境）
- 多行脚本统一用 `@'...'@ | Out-File -FilePath xxx.py -Encoding utf8`
- `head` 替换为 `Select-Object -First N`
- 大段替换优先用行号切片，不用字符串匹配
- 字符串匹配替换必须加 `assert old in text` 前置校验

## 十二、半自主执行规范

### 执行模式定义

Claude Code 默认以半自主模式运行：
- **验证门通过后**，自主完成执行步骤和测试，不需要每步等待
- **碰到硬停点时**，立即停止，完整报告当前状态，等待李Sir确认
- **SPEC 明确标注「需确认」的步骤**，执行完后等待确认再继续

### SPEC 标准结构

每份 SPEC 必须包含以下结构，缺少验证门的 SPEC 不得进入执行：

```
## SPEC-[编号] · [任务名称]

### 任务意图
[一句话：这个SPEC要实现什么，为什么]

---

### 验证门（只读，不修改任何文件）

#### 字段路径确认
- [ ] [描述项目]
      验证指令：grep -n "关键词" 文件完整路径
      预期结果：[描述预期位置或内容]

#### 逻辑边界确认
- [ ] [描述项目]
      验证指令：view 文件完整路径 第X~Y行
      预期结果：[描述预期的分支结构或返回值]

#### 验证结论
- 全部通过 → 报告「验证门通过」，进入执行步骤
- 任何一项不符 → 停止，逐项报告实际结果与预期的差异，等待SPEC修正
  不得自行推断继续执行

---

### 执行步骤
[每步独立描述；步骤间有依赖的明确标注「依赖步骤X完成」]

---

### 完成标准
[可量化的验收动作，例如：146/146通过 / grep确认字段存在 / 云控制台时间戳更新]

---

### 禁止项
[不得触碰的文件 / 逻辑 / 方向]
```

**写不出验证门 = 设计本身还没想清楚。** 这是质量过滤器，不是形式要求。

### 硬停点清单（触发即停，不得继续）

| 编号 | 触发条件 |
|------|----------|
| H1 | 测试失败，且失败原因需要逻辑判断（不是语法/路径/拼写等机械错误）|
| H2 | 执行路径触及 CORE_LOGIC.md「已确认废弃项」中的任何关闭路线 |
| H3 | 需要新增或修改字段语义（不是字段值，是字段的含义或数据结构）|
| H4 | 需要跨文件数据链路变更 |
| H5 | 任何部署动作（执行完成后强制等待确认）|
| H6 | 执行中发现 SPEC 未覆盖的上游问题 |

### 自主修正范围（无需等待，可自行修正）

- 字段名拼写错误
- 文件路径引用错误
- 语法错误
- 测试失败原因明确为以上机械错误之一，且修复不涉及逻辑判断
